# SHER · Guía de trabajo

SHER es una plataforma de invitaciones digitales. `docs/SHER-SPEC.md` es la fuente de verdad de producto y `docs/ARCHITECTURE.md` describe la arquitectura existente.

XV-01, XV-02 y XV-03 son plantillas existentes: no las rediseñes salvo solicitud explícita.

Para cambios no triviales:

1. Inspecciona el código y la fuente de verdad.
2. Propón o confirma un plan cuando corresponda.
3. Implementa el cambio mínimo coherente.
4. Ejecuta las validaciones aplicables.
5. Revisa el diff.
6. Reporta evidencia.

- Usa únicamente scripts existentes en `package.json`.
- No afirmes que una validación pasó si no se ejecutó.
- No inventes productos, precios, plantillas ni funcionalidades.
- No modifiques los assets originales de marca.
- No añadas dependencias sin justificación.
- No hagas commit, push, merge o deploy salvo solicitud explícita.
- Evita cambios en archivos no relacionados.
